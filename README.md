# Polyclinic Website

Учебный Django-проект для автоматизации работы поликлиники. Приложение показывает справочники врачей и пациентов, ведёт визиты, поддерживает операторские действия и формирует отчёты по приёмам.

## Стек и архитектура

- **Backend:** Django.
- **База данных:** PostgreSQL.
- **Доступ к данным:** ORM + SQL-запросы в отдельных отчётах/списках.
- **Роли доступа:**
  - обычный режим — просмотр справочников и отчётов;
  - операторский режим — создание/редактирование/удаление визитов и массовая отмена записей.

Проект использует существующую схему БД (`managed = False` у моделей), поэтому ключевая структура хранится в SQL-скрипте `bd_project.sql`.

## Основные возможности

- Главная страница со сводной статистикой по врачам, пациентам и визитам за день.
- Справочники:
  - врачи;
  - пациенты;
  - визиты;
  - расписание врачей.
- Операторские действия:
  - создание визита;
  - редактирование визита;
  - удаление визита;
  - отмена всех запланированных визитов выбранного пациента.
- Отчёты:
  - агрегированная статистика по врачам;
  - список предстоящих визитов выбранного врача.

## Ограничения и бизнес-правила

Проверки записи к врачу реализованы в модели `Visit.clean()`:

- время визита должно быть кратно 30 минутам;
- врач должен быть доступен для записи;
- визит должен попадать в рабочее время врача по расписанию;
- в базе действует уникальность слота врача: `(doctor, visit_date, visit_time)`.

## Быстрый запуск

### 1. Установить зависимости

```bash
cd polyclinic
python -m venv .venv
source .venv/bin/activate  # Windows: .venv\Scripts\activate
pip install -r requirements.txt
```

### 2. Подготовить PostgreSQL

1. Создать БД `polyclinic_db`.
2. Выполнить SQL-скрипт `bd_project.sql`.
3. Создать пользователей БД (как в `settings.py`):
   - `polyclinic_operator` (операции записи/изменения);
   - `polyclinic_client` (режим чтения).

> При необходимости скорректируйте параметры подключения в `polyclinic/polyclinic/settings.py`.

### 3. Запустить приложение

```bash
cd polyclinic
python manage.py runserver
```

После запуска откройте: `http://127.0.0.1:8000/`.

## Режим оператора

В проекте предусмотрено переключение в операторский режим через UI:

- вход: `POST /operator/login/`
- выход: `POST /operator/logout/`

Тестовый пароль для входа в режим оператора (из текущей реализации): `123`.

## Полезные URL

- `/` — главная.
- `/doctors/` — список врачей.
- `/patients/` — список пациентов.
- `/visits/` — список визитов.
- `/schedules/` — расписание врачей.
- `/reports/doctor-stats/` — статистика врачей.
- `/reports/next-visits/` — предстоящие визиты врача.
- `/visits/create/` — создание визита (оператор).
- `/visits/edit/<id>/` — редактирование визита (оператор).
- `/visits/delete/<id>/` — удаление визита (оператор).
- `/cancel-appointments/` — массовая отмена визитов пациента (оператор).

## Замечания по безопасности (для учебного проекта)

- В репозитории указаны демонстрационные креды БД и `SECRET_KEY`.
- Пароль входа в операторский режим захардкожен.
- Для production-среды обязательно вынести секреты в переменные окружения, ограничить `ALLOWED_HOSTS`, отключить `DEBUG`, и организовать полноценную аутентификацию/авторизацию.
